These three logs are genuine output from the installed simulator, trimmed by
line slicing only (no value was edited). They document the default CE circuit
form used by the integration tests:

```
analysis=dc/ac/tran, vcc=12 V, r1=100 kΩ, r2=22 kΩ, rc=2.2 kΩ, re=1 kΩ,
rl=10 kΩ, cin=10 µF, cout=10 µF, amp=10 mV peak, freq=1 kHz
```

| File | Contents | Real size |
| --- | --- | --- |
| `dc.op.log` | banner, node-voltage table, source currents | 1 operating point |

| `tran.wave.log` | initial operating point and first 20 rows of `v(in)`/`v(out)` | full run: 2008 points over 5 ms |

## Reproduction (PowerShell, from the repository root)

The netlists are generated by the production builder, then ngspice is run in
batch mode. `run_analysis()` passes `-r`, which makes ngspice 47 print
`.print line ignored since rawfile was produced.` and write no table into the
`-o` log; the app therefore parses the **binary raw file**. These samples were
captured from the *same netlists without `-r`* so that the real `.print` tables
are visible. The AC gain and phase appear as two separate four-column tables
on this build.

```powershell
$env:NGSPICE_EXE = 'C:\Users\B6807092\AppData\Local\ngspice-47\clang64\bin\ngspice.exe'
.\.venv\Scripts\python.exe -c "from pathlib import Path; from spice_engine import build_netlist, parse_sim_form; d=Path('docs/spice-samples/repro'); d.mkdir(parents=True, exist_ok=True); form={'vcc':'12','r1':'100','r2':'22','rc':'2.2','re':'1','rl':'10','cin':'10','cout':'10','amp':'10','freq':'1'}; [ (d/(a+'.cir')).write_text(build_netlist(parse_sim_form({**form,'analysis':a}), str(Path('spice/q1_npn.model').resolve())), encoding='utf-8') for a in ('dc','ac','tran') ]"
& $env:NGSPICE_EXE -b -o docs/spice-samples/repro/dc.full.log docs/spice-samples/repro/dc.cir
& $env:NGSPICE_EXE -b -o docs/spice-samples/repro/ac.full.log docs/spice-samples/repro/ac.cir
& $env:NGSPICE_EXE -b -o docs/spice-samples/repro/tran.full.log docs/spice-samples/repro/tran.cir
.\.venv\Scripts\python.exe -c "from pathlib import Path; d=Path('docs/spice-samples/repro'); out=Path('docs/spice-samples'); specs={'dc.op.log':('dc.full.log',[(0,32)]),'ac.bode.log':('ac.full.log',[(0,16),(16,36),(164,169),(169,189)]),'tran.wave.log':('tran.full.log',[(0,31),(31,51)])}; [(out/name).write_bytes(b''.join(b''.join((d/src).read_bytes().splitlines(keepends=True)[a:b]) for a,b in sl)) for name,(src,sl) in specs.items()]"
```

The `repro/` directory and `*.full.log` files are temporary artifacts and are
gitignored; only the three trimmed samples above are committed. Line slices
assume ngspice 47-1 with the directives in the generated netlists
(`.op`, `.ac dec 20 1 10Meg`, `.tran 2.5e-06 0.005`).

## Collector-current sign source (observed real numbers)

The DC binary raw file contains `v(b)`, `v(c)`, `v(e)` and voltage-source
branch currents `i(vin)`, `i(vcc)` — it does **not** contain `i(rc)`, and with
`-r` ngspice does not emit the `.print op ... i(rc)` table into the log.

- `i(vcc) = -1.4239558663289907e-03 A` (negative: current leaves the supply)
- `-i(vcc) = +1.4239558663 mA` → reported `ic_ma` (positive), with warning
  `i(rc) missing; used -i(vcc) for ic_ma`
- RC-drop estimate `(12 - 9.0872162552) / 2200 = 1.3239921567 mA`
- Difference `0.0999637 mA` is the R1/R2 divider plus base current that also
  flows through VCC.

**Chosen source:** `-i(vcc)` on the real path (sign inverted to a positive
collector-current magnitude). The parser still prefers an explicit `i(rc)`
when a log supplies one. `-i(vcc)` is a supply-current approximation to Ic,
not the exact transistor collector current; the RC-drop value is the closer
estimate for this bias point.
